## Contract-level changes

| # | Change | Doc surface |
|---|--------|-------------|
| 1 | Desktop notifications now posted from the server utilityProcess to the Electron main process (`shared/notifications.ts` → `electron/notifications.ts`), restoring Cogpit icon, dock bounce, click-to-open deep link. `osascript` is now only the standalone-server fallback (macOS only). | New README section; new architecture ownership row |
| 2 | Codex wired alongside Claude Code. `/api/notify` normalizes two payload shapes: Claude snake_case on stdin (`Stop`/`Notification` hooks), Codex kebab-case `agent-turn-complete` as final argv element (`notify` config key). Hook script itself lives outside this repo (`~/.agents/bin/cogpit-notify.sh`). | README (contract documented, script not claimed as shipped) |
| 3 | **New:** ntfy phone push. Config `~/.cogpit/push.json` (`topic`, `ntfyUrl`, `token`, `publicUrl`) with env overrides `COGPIT_NTFY_TOPIC` / `COGPIT_NTFY_URL` / `COGPIT_NTFY_TOKEN` / `COGPIT_PUBLIC_URL`. Re-read on file/env change, no restart. Push fires only when unattended: no window, locked/suspended, or ≥120 s system idle. Headless is always unattended, so push is its only working channel. | README table |
| 4 | **New:** bound port published to `~/.cogpit/port` (mode 0600, removed on exit) from both Electron worker and standalone. Hook resolution order `$COGPIT_PORT` → port file → `19384`. | README; CLAUDE.md + AGENTS.md External Session API |
| 5 | **Behavior change:** Cogpit-spawned sessions are no longer excluded from notifications (the `persistentSessions` filter is gone). Presence decides, not provenance. Cooldown is now per-session (5 s) instead of one global timestamp. | README (cooldown noted); no prior doc asserted the old filter |
| 6 | `vitest.config.ts` includes `electron/**/*.test.ts` (node environment). | CLAUDE.md + AGENTS.md testing policy |
| 7 | `/api/notify` body cap 64 KB → 4 MB, `413` over. `readJsonBody` now decodes UTF-8 across chunk boundaries (affects every route; no doc asserted the old corruption). | ios/API_MAP.md route table |

No breaking changes: push is inert until a topic is configured, the port file is additive, and the notification payload contract is inbound-only (hooks, not clients).

## Flagged, not changed

- `ios/DESIGN.md:15` lists "push notifications (needs server-side APNs)" as a v1 non-goal. Still literally true — the native app has no push; ntfy delivers to a third-party app, bypassing APNs entirely. Left as-is rather than editing a separate repo's design doc on a technicality; API_MAP gotcha #18 now carries the clarification a reader needs.
- `README.md:170` Tech Stack still lists **Radix UI**; the codebase migrated to Base UI on 2026-03-07. Pre-existing drift, already flagged in the `28db8d3` audit, unrelated to this commit.
- `~/.cogpit/push.json` mode 600 is documented as user guidance, not enforcement: `server/lib/pushConfig.ts` reads the file and `statSync`s it only for mtime — it does not reject a world-readable config. Worth an enforcement check or a startup warning; documenting it as enforced would have been false.
