## Changes Summary

### Implementation Overview

The session archive feature adds server-side persistence of session visibility state:

- **Manual archiving**: users archive/restore via sidebar UI or context menu
- **Auto-archiving**: sessions with 14 days of transcript inactivity auto-archive (unless user restored)
- **Auto-unarchive**: transcripts written after archiving (e.g., sending a message) auto-restore if write timestamp > archive time + 2 minutes grace period
- **Server-wide state**: stored in `archived-sessions.json` under session-config dir, syncs across all devices

### API Additions

**Endpoint:** `POST /api/archive-sessions`
- Body: `{ "sessionIds": ["...", "..."], "archived": true }`
- Response: `{ sessionIds, archived, changed }` (changed = IDs with state actually modified)
- Archive reasons: `"manual"` (user action) or `"inactive"` (auto-archived)

**Endpoint:** `GET /api/active-sessions` (modified)
- New query parameter: `?archived=include` to include archived sessions in results
- New response header: `X-Cogpit-Archived-Count` (number of archived sessions matching query)
- New session fields: `archived` (boolean), `archivedReason` ("manual" | "inactive")
- Behavior: archived sessions excluded by default, never crowd per-project cap; searches always include them
