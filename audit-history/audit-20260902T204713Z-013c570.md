I reviewed the full tracked diff and every new source and test file for the GitHub Actions panel redesign and the Vercel Deployments plugin. The audit covered:

## Behavior documented

- The GitHub Actions panel now groups runs by commit, adds branch and failure filters, and presents jobs and steps in a denser expandable view. Its authenticated, read-only `gh` integration is unchanged.
- The new Vercel Deployments panel resolves only `.vercel/project.json` at the active session root. It does not search parent or child directories for another Vercel project.
- The server requires Vercel CLI 50.5.1 or newer before it can run `vercel api`. That version gate prevents older CLIs from treating the unknown `api` command as a deployment path.
- Authenticated `vercel api` calls list deployments and fetch build output only when a deployment is expanded. The plugin does not deploy, promote, redeploy, or roll back.
- Missing CLI, old CLI, authentication, project-link, and access errors remain isolated to the panel. Automatic polling pauses for setup errors until the user retries.
- Both new Vercel endpoints inherit the existing admin-only host-data policy.

## Documentation changes

- `docs/plugins.md` already had the required Vercel setup, minimum CLI version, exact-root behavior, read-only scope, registration boundary, and failure-isolation details.
- Updated `README.md` because it still described GitHub Actions as the only bundled plugin. It now names both integrations and summarizes the Vercel minimum version, exact-root link, read-only behavior, and isolated setup errors.
- `docs/architecture/README.md` remains accurate. The Vercel route uses the canonical route manifest, shared browser-safe contracts, and the existing root-plugin import boundary.
- No deployment registry update is needed. This change adds a deployment viewer but does not deploy or move Cogpit or Honest CMS.

## Result

Active documentation now matches the implementation. No public runtime-plugin installation, third-party backend route registration, deployment mutation, or recursive Vercel project discovery is implied.

**Risk:** MEDIUM. The new server integration reads host project metadata and invokes an authenticated external CLI, but exact-root resolution, strict deployment ID parsing, CLI version gating, admin-only access, response normalization, and focused tests limit that risk.
