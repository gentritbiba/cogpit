# Composer model picker popover refactor

Status: PASS. UI refactor and documentation audit complete.

The composer's six discrete chips (provider, model, reasoning-effort, Fast toggle, Ultracode toggle, MCPs dropdown) consolidated into one popover panel opened by the model chip beside Send. The panel contains a provider column, model list, reasoning-effort segmented control, Fast icon toggle and Ultracode text toggle in the Model header; it stays open on inner clicks and closes on outside click or Escape. For new sessions it opens downward; for live sessions it opens upward. Permissions and MCPs pickers use the same popover shell. The settings row moved from below the ChatInput to a `footer` prop inside ChatInput, rendering via SessionInputFooter with translucent blurred surface (`--composer-surface` token) and gradient fade. The "Changes apply live" hint was removed from desktop (mobile retains it per design). Bug fix: catalog helpers in `src/lib/utils.ts` now require explicit `options` parameter; components use new `useModelCapabilities` hook to ensure React Compiler does not memoize old store-reading calls that skipped Fast for the default Claude model. `useMcpServers` gained a `setSelection` bulk setter (not yet used by UI).

Documentation audit: README.md already updated in the diff with the correct description of the model chip opening one panel with provider, models, reasoning-effort ladder, and Fast/Ultracode modes. No other production documentation mentioned the specific UI elements changed (chipset, popover design, settings row placement, footer prop). Plan files under docs/plans/ and docs/ui-simplification.md are historical records and correctly left unchanged per audit policy.

No breaking API changes. Backward compatibility maintained through ChatInput's optional footer prop (defaults to undefined). Popover and SessionInputFooter are internal presentation only.
