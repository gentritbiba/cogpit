# Cloudflare Workers runtime package

This package is `cogpit.cloudflare` version 1.0.0, a read-only right-sidebar panel with two views. **Workspace** covers the Cloudflare Worker configured in the current workspace: the signed-in Wrangler identity and account, the live deployment, the Worker's declared routes, cron triggers and bindings per environment, and the recent deployment history. Expanding a deployment loads that version's number, commit tag, compatibility settings, handlers and binding names. Binding and variable values are never read. **Account** lists every Worker in the account connected through Cogpit's Connections controls with an API token. React and the public plugin UI are bundled with the package.

The frame calls only the public SDK's `integrations.request` operations `workspace`, `deployments` and `version`, the declared `workers` connection operation, `connections.status`, plus `navigation.openExternal` for dashboard links. It receives an opaque project identity and never chooses a workspace path, a Wrangler binary or CLI arguments; a `config` argument may only name a configuration the host itself discovered. The host runs Wrangler on the exact active-session workspace with `--config` pointing at the discovered file and `--env` limited to environments that file declares. The connection definition in `connections/cloudflare.json` binds the account-wide read to the account selected on the host; the token never reaches the frame.

The host looks for `wrangler.json`, `wrangler.jsonc` or `wrangler.toml` in the session directory, then in each parent up to the Git worktree root, without searching sibling apps or other worktrees. When none exists it scans the workspace's subfolders up to three levels deep, skipping `node_modules`, build output and hidden folders, and the panel offers a picker for every project found. It prefers the project's own `node_modules/.bin/wrangler` between that directory and the repository root, then `wrangler` on the host PATH. That runs the repository's installed Wrangler with the host's environment, the same trust the agent CLIs already extend to the workspace; do not open the panel on a repository you would not run `wrangler` in. Wrangler must be 4.65.0 or newer, the release that added `wrangler whoami --json`. Authentication comes from `wrangler login` on the host or `CLOUDFLARE_API_TOKEN`; the account comes from `account_id` in the configuration, `CLOUDFLARE_ACCOUNT_ID`, or the only account the token can see. Pages projects, live tails and every write operation are out of scope.

Missing configurations, invalid configurations and Workers that have not been deployed yet are checked again every thirty seconds while the panel is visible. Missing or outdated Wrangler, sign-in and account problems wait for an explicit refresh.

Run `bun run build:runtime-plugins` from the repository to produce the standalone archive. `bun x tsc -p plugins/cloudflare/tsconfig.runtime.json` verifies the independent runtime source. The signed manifest source is `plugin.json`, the runtime entry is `runtime.tsx`, and styles come from the public UI stylesheet.

`NOTICE` records the third-party package versions and license texts in the rendered production module closure, which is the same closure as the Vercel package: the same React, public UI and icon dependencies. Regenerate it when that closure changes.
