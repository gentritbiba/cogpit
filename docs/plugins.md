# Workspace plugins

Plugins can contribute workspace panels, settings fields, agent skills, inline chat cards, buttons that request an agent task and composer dictation. These contributions are independent: a skills-only or settings-only package needs no JavaScript entry or placeholder panel. Settings, skills, chat cards and session actions require plugin API 1.2.0; dictation, action icons and recording uploads require 1.3.0. The Text to speech package is a minimal example under `plugins/tts/`.

## Settings, skills and chat cards

`contributes.settings` declares a `plugin` or `project` scope and up to 32 fields. Supported field types are `string`, `number`, `boolean` and `select`, with validated defaults and bounds. They appear under Configuration → Manage plugins → the installed plugin's Settings button. Credentials belong in a declared connection, not a settings field. Values are private to the authenticated principal and host; project settings are additionally isolated by canonical project identity. Saves use an expected revision, so a stale form cannot overwrite another client's changes. Disable retains settings; explicit own-data deletion removes them with the plugin's other saved data.

Settings use a separate namespace from general plugin storage. The host returns declared fields only, supplies defaults for new fields and retains removed fields for rollback. If an older saved value no longer matches a field's bounds, the form explains which fields are showing defaults until saved. `client.settings.get()` reads the current validated values. The settings value limit is 32 KiB; default values must fit within 16 KiB. Incompatible `stateVersion` changes retain the existing recovery behavior.

`contributes.skills` declares `{ id, title, description, source }`, where `source` is a signed Markdown asset. Each source is limited to 16 KiB and each package to 64 KiB of skill sources. Cogpit supplies enabled, workspace-scoped skills through its agent adapters, including isolated account workers. These supplementary instructions contain no connections or credentials and do not replace the user's or repository's instructions. They are refreshed when an agent query/thread is started or resumed; an already-running persistent query keeps its instruction snapshot until it is restarted. No user-owned global skill files are written or removed. The ACP adapter includes the same context with each prompt. Uninstalled/disabled/out-of-scope plugins and host safe mode contribute no new instructions.

`contributes.chatBlocks` declares `{ id, title, height }`. An agent writes a fenced block with language `cogpit:<publisher.plugin>:<block-id>`, for example:

````text
```cogpit:cogpit.tts:speech
Here are the words the user can turn into speech.
```
````

The host activates the registered package's existing sandbox with `context.surface = { type: "chat-block", id, source }`. The package receives only that block's source, capped at 16 KiB, plus its permitted public context. Blocks activate only inside agent replies in an authorized workspace, after normal compatibility and scope checks. Quoted prompts, streaming text and shared views without a plugin host remain ordinary Markdown. Missing, disabled, incompatible or failed plugins leave readable source text. Frames activate near the viewport and are disposed outside it, when the reply changes, or when host/user/permissions change. Opening a card must not perform a provider write; the package's explicit controls request those operations. `client.ui.resize(height)` requests a bounded height of 80–800 pixels.

`contributes.sessionActions` declares `{ id, title, icon?, skill, prompt }`. The referenced skill must be in the same manifest. Cogpit renders a composer button for the enabled, compatible plugin; clicking it sends the declared prompt through the session's existing send-permission and delivery path. With `icon` (currently `speaker`), the button is a compact icon that Cogpit draws itself, with the title as its tooltip and accessible name; without one it is a text button. A frame cannot invoke these buttons programmatically. Install/update review includes these actions and the instruction/card contributions.

`contributes.dictation` declares `{ title, connection, operation, text }` and adds a microphone button to the composer. Cogpit's own UI records, not the plugin: sandboxed plugin frames have no origin, and Chromium refuses them the microphone. Recording starts only when the button is pressed, shows a level meter and a Stop button, and turns the microphone off when it ends. Stop inserts the transcript at the end of the draft, the composer's Send button (or Enter) transcribes and sends the whole draft, and Escape discards the take. Takes are limited to four minutes and are kept in memory only, so a failed transcription can be retried. Cogpit sends the take as 16 kHz mono 16-bit WAV to the named connection operation, which must be a granted upload operation accepting `audio/wav` with no required arguments. The host reads the transcript at the `text` JSON pointer of the answer and returns only that string. A client needs a secure context (localhost or HTTPS) to record; elsewhere the button is hidden. The desktop app asks macOS for microphone access the first time.

## Declared POST operations and audio

Connection operations can declare `POST` and a JSON `body` using the same literal, argument, validated-resource and identity bindings as query fields. New numeric arguments support fractional values; bounded multiline string arguments must opt into `multiline`. Setup/credential-validation operations remain GET requests returning JSON. Arbitrary origins, paths, headers, CLI arguments and credentials are still unavailable to a package; the existing public-HTTPS destination policy, DNS pinning, authorization, cancellation and response limits apply.

An upload operation declares `upload: { type: "audio", mimeTypes, maxBytes }`: it is a panel POST without a JSON `body` or audio response, and its request body is a recording from Cogpit's dictation control, sent with its own Content-Type. Frames cannot call upload operations, and other calls cannot reach them. Uploads share the 8 MiB media cap, including through hub relays.

An audio operation declares `response: { type: "audio", mimeTypes, maxBytes }` and is called through `client.connections.media(handle, operationId, args)`. JSON calls cannot consume audio operations or vice versa. The host buffers at most 8 MiB of declared audio per request, permits four simultaneous audio requests, validates the MIME type and stream completion, and transfers bytes to the frame as an ArrayBuffer. The SDK returns a Blob. The plugin creates a local blob URL and revokes it when no longer needed. No credential or provider download URL enters the frame. The sandbox permits blob audio only and still has no direct network access. The same media cap applies through hub relays.

## Text to speech MVP

Install Text to speech from Browse, open its Settings, connect the speech service and choose a voice. The API key stays on the selected Cogpit host. Speed and MP3/WAV preferences live in the declared settings. A speech card generates audio only when its button is pressed, supports cancellation, and presents playback controls. Audio is ephemeral and is released when the card leaves the viewport or its session closes; the original text remains in the transcript.

The composer’s Spoken summary action, a speaker icon beside Send, asks the current agent for the shortest useful summary in ordinary spoken prose, with no lists, numbered points or headings. Users can also ask directly, or tell the agent to summarize after every turn. The plugin skill explains these choices; it does not add a summary to every reply by default.

Text to speech 1.1.0 also provides dictation through the same connection and API key: the microphone button records, and the speech service's `POST /v1/transcribe` answers once with the final text of the whole take (Parakeet on Omarchy), rather than streaming partial text the way its live WebSocket does.

Clients that cannot host plugin frames, such as the iOS app, use the same connection, voice and settings through `POST /api/voice/speech {text}`, which returns the audio, and transcribe through the plugin's dictation with `POST /api/voice/transcribe` (a WAV body, answering `{text}`). A `503 voice_not_configured` from either tells the client to use the device instead. The iOS voice mode sends messages with `voice: true` on `/api/send-message`; the server appends a hidden `<cogpit-voice-mode>` instruction asking the agent to announce results and ask questions inside a speech block.

The bundled example targets an OpenAI-compatible speech service and binds synthesis to the voice selected through its authenticated discovery operation. Provider errors that occur after a streaming 200 response can still result in partial audio: the host rejects empty/incomplete HTTP bodies and the card reports browser playback errors, but cannot prove a successfully decoded audio stream contains the entire intended speech. The service should validate parameters before sending response headers.

## Release-owned integrations

Some packages turn on code that ships with Cogpit rather than with the package. The host grants these only to a plugin whose selected package is the exact release-bundled bytes or is signed by a pinned official root (`privilegedPluginIds` in the plugin snapshot); a publisher name alone never qualifies.

- `worktreeSetup` (host): runs a project's trusted setup command before a new worktree's first prompt. See [Worktree setup](worktree-setup.md).
- `composer.drafts` (client): the `drafts` composer permission lets a plugin list, save and restore composer drafts through `src/clientIntegrations/composer-drafts/`. The browser activates it while the plugin is enabled and granted, whether or not its panel is open, and disposes it, keeping data, on disable or uninstall. Frame requests carry the composer token and are authorized by the host under the frame's lease first. Images never enter the frame.

ClickUp, GitHub, Vercel and Cloudflare render in Cogpit's existing right sidebar. Their panels are separate runtime packages, loaded after installation without rebuilding or restarting Cogpit. The host owns installation, so desktop and remote browser clients share the installed versions and enabled state.

Fresh hosts start with no optional plugins installed. Open Plugins, choose Browse, and review a bundled package's access before installing. Existing hosts migrate the three original panels once to preserve current behavior; Cloudflare is new and is only ever installed on request. Disable keeps settings and connections. Uninstall retains data unless the user explicitly chooses to delete their saved data on that host. An uninstall is remembered across app updates.

The GitHub, Vercel and ClickUp packages retain their existing panel behavior, and Cloudflare joins them:

- **GitHub** uses the host's signed-in GitHub CLI. Actions shows workflow runs, jobs and steps. Pull requests shows checks, reviews, files and related Cogpit sessions; while checks run, the row's ring fills as each check reports, and clicking it opens the Actions tab on that branch when the checks come from GitHub Actions, or the pull request's checks page otherwise. A pull request GitHub would accept shows a Merge button that expands into an inline confirmation with the repository's allowed merge methods; the merge is pinned to the head commit that was displayed. When the open chat session opened or worked on pull requests in the repository, a **This session** tab appears first and is selected on arrival, showing just those pull requests (a lone one starts expanded). Issues supports filtering and adding an issue to the composer draft. Install `gh` and run `gh auth login` on the connected host.
- **Vercel** uses Vercel CLI 50.5.1 or newer. Run `vercel login` and `vercel link` in the workspace or its repository root to show deployments and build logs. Cogpit uses the nearest `.vercel/project.json` between the session directory and its Git worktree root. It never searches sibling apps, other worktrees or above the repository; non-Git folders require their own link. An invalid nearer link must be fixed instead of falling back to another project. Vercel plugin 1.0.1 checks an unlinked workspace again every ten seconds while visible, and preserves cached deployments during refresh. Logs are checked against the linked project's deployment before retrieval. All operations are read-only.
- **Cloudflare** has two views. **Workspace** uses Wrangler 4.65.0 or newer, found first in the project's own `node_modules/.bin` between the configuration directory and the repository root, then on the host PATH. It reads the nearest `wrangler.json`, `wrangler.jsonc` or `wrangler.toml` between the session directory and its Git worktree root, with the same no-sibling, no-other-worktree rule as Vercel; when none exists it scans the workspace's subfolders (three levels deep, skipping dependency and build folders) and offers a Worker picker for every project found. The view shows the signed-in identity and account, the live deployment, declared routes, cron triggers and binding names per environment, and recent deployments; expanding one loads that version's number, commit tag, compatibility settings and binding names. Variable and secret values are never read. Authentication is `wrangler login` on the host or `CLOUDFLARE_API_TOKEN`; the account is `account_id` in the configuration, `CLOUDFLARE_ACCOUNT_ID`, or the only account visible. Pages projects, live tails and all writes are out of scope. Missing configurations and undeployed Workers are checked again every thirty seconds while visible. **Account** lists every Worker in a Cloudflare account through the trusted Connections controls: paste an API token with Workers Scripts Read and Account Settings Read, pick the account, and the panel shows each Worker's name, last change, handlers and dashboard link, refreshed every minute while visible. The token stays on the host and only the declared `workers` read is granted to the panel.
- **ClickUp** shows My tasks and This project, including existing filters, task details, draft actions and closed-task folding. The trusted Connections controls collect credentials and select the workspace, space and list. Credentials remain on the connected host. Existing `~/.cogpit/clickup.json` settings are backed up and imported once. `COGPIT_CLICKUP_TOKEN` or `CLICKUP_API_TOKEN` remains a read-only host environment override.

Missing or outdated CLIs and missing connections produce setup guidance in the panel. Disabling or removing a plugin cancels its requests and removes its sidebar entry. Browser safe mode pauses plugins only in that browser. Host safe mode disables execution for every connected client.

## Loading and project cache

Each runtime panel keeps its three most recently visited project/workspace views mounted in the browser. Returning to a cached project shows its existing data immediately, then the panel's normal background refresh checks for changes. Hidden views stop provider polling and cancel pending reads. Evicting the least recently used view disposes its iframe and lease. Switching chat sessions within the same workspace preserves project data and cancels actions tied to the previous chat.

The cache is private to the connected host and signed-in session. Plugin changes, permission changes, connection changes, safe mode and host disconnection clear affected activations. It is an in-memory cache, not offline persistence. Closing the containing workspace or reloading the app releases it.

Project discovery remains separate from request validation. Runtime reads re-resolve the selected canonical workspace and its Git identity before and after the operation, checked against a project inventory snapshot at most 30 seconds old. A workspace or project missing from the snapshot triggers a fresh inventory read, so new projects and worktrees are recognized immediately; a project leaving the inventory or a nested folder becoming its own project takes effect within 30 seconds. Every native subprocess retains live permission and cancellation checks. Readiness validates the existing lease without loading provider data or repeating project discovery.

## Package contracts

New packages use `@cogpit/plugin-sdk`, with optional `@cogpit/plugin-ui` and public data types from `@cogpit/plugin-integrations`. Packages cannot import Cogpit source, sibling plugins or private session types. The package build and architecture checks enforce these boundaries. `src/plugin-api` is internal to Cogpit's core workspace panels.

A package declares its identity, immutable version, client and host requirements, panel contribution and permissions in `plugin.json`. Installation checks these requirements before activation. Review screens show added or removed access for updates. Bundled first-party packages use release-owned bytes; uploaded packages are signed by a publisher the host has enrolled. `@cogpit/plugin-tools` provides the `cogpit-plugin` CLI that creates a development publisher and signs a built directory into a `.cogpit-plugin` file, so new packages install through Plugins → Publishers and Install from file without rebuilding Cogpit; `bun run plugins:pack <plugin>` does this for the bundled sources. The online catalog is deferred.

ClickUp uses declared HTTPS connection operations. GitHub, Vercel and Cloudflare use a bounded `client.integrations.request()` operation list. The host supplies the selected workspace and permits only the declared operations; the one write, GitHub `mergePull`, is listed separately in the install review and takes a pull request number, an allowed method and the full head commit SHA, nothing else. Packages cannot supply shell commands, arbitrary CLI arguments, credentials or a different workspace path. Related session links use opaque handles; only Cogpit's trusted parent resolves storage addresses and opens a session. A plugin granted `session.identity` also receives the open chat session in `context.session` as the same kind of handle, so it can recognise that session among related ones without learning its title, path or id.

Panels receive public project identity, theme, locale, visibility and motion preferences. External links and draft actions pass through the SDK. Hidden panels stop provider polling. Sidebar indicators use the same host authorization without keeping a hidden plugin frame running.

The public packages remain unpublished in this working tree.
