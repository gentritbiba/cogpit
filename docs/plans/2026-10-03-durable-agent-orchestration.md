# Durable agent orchestration

User authorization: implement all improvements from the T3 comparison, including concurrent account instances, a generic ACP integration, and generated protocol contracts. Preserve native CLI history and the existing agent/edition boundaries. No public push, PR, deployment, login switch, or deletion of user state is authorized by this implementation task.

## Implementation

1. Add a host-owned transactional orchestration store for durable async requests, command receipts/dispatch queue, stable conversations/native bindings, sequenced events, and delegated tasks/completion delivery. Use built-in SQLite only after verifying Node/Electron/Bun support; lazy initialization follows the configured data root, owner-only files, versioned migration, transaction rollback, and explicit corruption errors. Tests use temporary roots, never real user history.
2. Persist Codex async questions; retain across turns, close, and restart. Validate per-question answers and resolve the specific request only together with accepted answer-message intent. Live RPC approvals remain process-bound and expire on process loss.
3. Route ordinary UI/CLI sends through one durable dispatch service. Add scoped command/message IDs, payload fingerprints, stable receipts, explicit delivery states, per-session serialization, editable/reorderable/cancellable queues, and steer/restart intent. Record dispatch intent before I/O. On restart hold unsent work and mark ambiguous in-flight delivery unknown; never blindly replay provider effects. Admission does not mean provider execution completed. Preserve authorization and edition turn hooks on every path.
4. Register stable conversation IDs and native session bindings at creation and when opening existing history. Retain legacy native-ID APIs. Provide explicit provider transition policy (compatible resume vs bounded textual handoff), carry conversation metadata, and keep native transcripts intact. Wire transitions and queue controls into the conversation UI and CLI.
5. Add durable delegated-task/result delivery behind SessionHost and the CLI. Track parent/task/source IDs, completion disposition, acknowledgements, and timeout-vs-cancellation. Use stable command IDs for agent sends and parent wakeups, respecting permissions and remote host ownership. Provide MCP discoverability over the same services without an independent execution path.
6. Introduce a shared client connection owner per environment/stream with reference-counted subscriptions, jittered reconnect, auth-loss handling, foreground health checks, separate transport/freshness state, and cursor replay/snapshot fallback for durable app events. Retain native transcript byte offsets and token overlays; advance a cursor only after applying state.
7. Add provider configuration/account instance IDs with isolated runtime scopes, homes/auth/cache and explicit continuation compatibility. Do not copy active credentials or switch the user's current CLI login. Expose setup/selection/removal in settings; refuse deletion while active and avoid assuming profile separation creates a filesystem sandbox.
8. Add a generic ACP agent beneath the agent descriptor/runtime/format/store layer. Use the stable official protocol, negotiate capabilities, retain native permission IDs, support creation/load/prompt/cancel and streamed updates, and keep unsupported native rewind/fork disabled. Persist its app-owned transcript and configure executable/argv/instances through the provider settings. Generate Codex protocol types/schema metadata from a recorded upstream/CLI version, with checked-in provenance and a drift check; retain backward-compatible decoding.
