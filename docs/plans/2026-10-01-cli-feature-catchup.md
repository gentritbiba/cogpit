# CLI compatibility audit — 2026-10-01

Cogpit now targets Claude Code 2.1.287 through Agent SDK 0.3.287 and supports the applicable additions in Codex CLI 0.159.3. These changes are local and unreleased.

## Comparison baseline and sources

The previous audit was [September 11, through Claude Code 2.1.268 and Codex 0.154.0](2026-09-11-cli-feature-catchup.md). This one covers Claude Code 2.1.269–2.1.287 and Codex stable releases 0.155.0–0.159.3.

Primary sources:

- [Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), entries 2.1.269–2.1.287.
- Agent SDK 0.3.287 TypeScript declarations (`sdk.d.ts`, `sdk-tools.d.ts`), diffed against 0.3.270.
- Codex release notes for [0.155.0](https://github.com/openai/codex/releases/tag/rust-v0.155.0) through [0.159.3](https://github.com/openai/codex/releases/tag/rust-v0.159.3), the app-server JSON schema generated by the installed CLI (`codex app-server generate-json-schema --experimental`), and the 0.159.3 source for wire details the schema leaves open.
- Installed binaries: `claude --version` → 2.1.287; `codex --version` → 0.159.3. Runtime checks used SDK `supportedCommands()` / `supportedModels()`, headless runs of individual slash commands, a live `model/list` request and `codex features list`.
- Transcripts on disk: every record type, attachment type and top-level key written by Claude Code 2.1.269+ and Codex 0.155+ on this machine, compared with what the parsers handle.

## Implemented

### Claude Code

| Change | Cogpit behavior |
| --- | --- |
| Claude SDK update | Dependency and lockfile move from 0.3.270 to 0.3.287, including the bundled 2.1.287 CLI. |
| Ultracode is its own toggle (2.1.284) | Ultracode no longer forces Extra High effort. A session launches with the selected effort and `ultracode: true`. Changing effort on a live session re-sends `ultracode` with the new level, because an effort change without that key switches Ultracode off. The effort slider stays adjustable on web, mobile web and iOS. A session with no stored effort now resolves it from the transcript whether or not Ultracode is on. |
| Local slash command output | `/usage`, `/context`, `/recap` and similar commands write their answer as a `system` record with subtype `local_command`, which the parser dropped: the command ran and the timeline showed nothing. It is now a `local_command` content block on the turn that ran the command, rendered with the existing command-output card on web and iOS and returned by `cogpit-memory context` and `/api/session-context`. The block never opens a turn, so turn boundaries are unchanged. |
| Headless commands | `/usage`, `/context`, `/recap`, `/rename`, `/goal`, `/autocompact`, `/mcp` and the `/doctor` skill join the slash suggestions. Each was run headless against 2.1.287 before being listed, except `/goal`, which Cogpit's goal control already sends. `/doctor` was previously left out as terminal-bound; it is now a skill that runs as a normal turn. |
| AGENTS.md as project instructions (2.1.277) | Claude Code reads a project's `AGENTS.md` when the project has neither `CLAUDE.md` nor `.claude/CLAUDE.md` (confirmed with `/context` in three fixture projects). The config browser adds the Claude badge to `AGENTS.md` under exactly that condition. |
| Models | The offline fallback list drops the separate `[1m]` rows: Opus 5.5, Sonnet 5.5 and Fable resolve to 1M-window models on their own. The live catalog from `supportedModels()` remains authoritative and already carries Opus 5.5 and Sonnet 5.5. |
| Error results | An error result with no `result` text now reports its `errors` list instead of a generic "Claude returned an error". That list is where 2.1.287 puts the cause of a startup failure. |
| Artifact tool | Summaries cover multi-file `upload_asset` (`file_paths`) and the `pin` / `unpin` actions. |

### Codex

| Change | Cogpit behavior |
| --- | --- |
| Models | The offline fallback catalog mirrors `model/list` from 0.159.3: GPT-6.1 Sol, GPT-6 Astra, GPT-6 Sol, GPT-6 Luna, GPT-5.6 Sol/Terra/Luna and GPT-5.5, with each model's default effort, effort range and Fast tier. GPT-5.4, GPT-5.4 Mini and GPT-5.3 Codex Spark are gone upstream and removed here. The iOS static catalog matches. |
| Plan names | The usage widget shows Codex plans by the CLI's display names (`promax` → "Pro (Max)", `prolite` → "Pro"). Unknown ids are shown as they are. |
| MCP tool-call approvals | With `tool_call_mcp_elicitation` on by default, Codex asks the client to approve an MCP tool call through `mcpServer/elicitation/request`. Cogpit answered every such request with "unsupported", so the call was refused. These now appear in the permission bar and Mission Control as "Run MCP tool", with Codex's question and the call's arguments. Allow accepts, Deny declines, and "allow for session" is offered only when Codex offers a session grant. The persistent "always" grant is never sent. |
| MCP server elicitations | Form and link requests from an MCP server in a Codex session reach the same Mission Control prompt Claude sessions use. Accept, decline and cancel map one to one. Pending requests are dropped on `serverRequest/resolved`, turn completion, thread close and disconnect. |
| Terminal-input approvals (0.158) | A command approval with `kind: "writeStdin"` is Codex asking to type into a terminal that is already running. It is shown as "Send input to a running terminal" with the keystrokes, control characters drawn (`⏎`, `^C`), instead of as a `write_stdin` command about to launch. |

## Changes handled by existing integration

Claude: Opus 5.5, Sonnet 5.5 and per-model effort availability flow through `supportedModels()`. MCP URL-mode elicitation already reaches the existing elicitation prompt. Cogpit always passes an explicit permission mode, so the CLI's new auto-mode default for unconfigured sessions does not apply. The stream bus ignores event types it does not know, which covers the new `ping` events. The removed `TaskOutput` tool keeps its label for older transcripts. Monitor's removed `persistent` option, background command time limits, the subagent hand-back frame, resume and prompt-cache fixes, and new settings (`attribution: false`, `deniedModels`, `allowedProviders`, `maxProseWidth`) need nothing from the host; the configuration editor preserves settings it does not know.

Codex: rollout files are unchanged. Records written by 0.155–0.159.3 use the same record and item types as 0.154. Worktrees became a stable, default-on feature in 0.156; the `--enable worktrees` flag Cogpit passes is now redundant there and still needed on 0.154–0.155. Reasoning efforts, Fast tiers and the default model come from the live catalog.

Terminal rendering, voice, themes, the TUI command center, fullscreen mode, the daemon and Windows-specific fixes are CLI surfaces. Claude gateway, cloud session, Slack and VS Code changes are separate products.

## Explicit boundaries

- Thinking duration (`thinkingDurationMs`, new on Claude assistant records) is not shown. Thinking blocks with no text are still skipped by the parser.
- SDK `prewarm()` (a spare process claimed on first send) is not used. Session start-up is unchanged.
- `CLAUDE_CODE_STARTUP_FAILURE_RESULTS` is not set, so startup failures that the CLI reports only on stderr still arrive as a process exit.
- The raw tool result of an Agent call now begins with the CLI's "[Subagent hand-back]" frame. The sub-agent panel shows the clean report from `toolUseResult`; the raw result is left as written.
- Claude Mods (2.1.287) change the terminal and desktop UI and have no surface in Cogpit.
- Codex requests Cogpit declines, each with a notice in the session: device verification (`openai/userVerification`), `openai/form`, approvals of kind `browser_auth` or `tool_suggestion`, a tool-call approval that also asks for input, forms with multi-select or nested fields, and links that are not http(s).
- `item/permissions/requestApproval` and blocking `item/tool/requestUserInput` are still answered as unsupported. Their features (`request_permissions_tool`, `default_mode_request_user_input`) are under development and off by default in 0.159.3.
- Elicitation prompts render on Mission Control cards only, for Codex as for Claude, and a session waiting on one still reports as running to `session-status`.
- `instant_interrupt` and compressed rollouts remain under development upstream and are not enabled.
- Codex 0.160.0 was published while this audit was being finished and is not covered.

## Verification

- Full root suite: 502 files, 8,182 tests passed, run with `COGPIT_PORT` and `COGPIT_SESSION_ID` unset. Two `codexBrowser` tests fail when `COGPIT_PORT` is set, as it is inside a Cogpit session; this work did not touch them.
- `packages/cogpit-memory`: 108 tests passed, each file run on its own. The three SQLite files still crash at teardown on Bun 1.4.0-canary.1 after reporting every test passing.
- Production and test TypeScript checks, ESLint, architecture, agent-vocabulary (130 files / 441 lines), memory-sync, skill-sync and duplicate-code gates passed. The duplicate ratchet was lowered from 63 clones / 555 lines to the measured 62 / 531.
- iOS: `swift run cogpit-checks` passed 474 checks, and `xcodebuild` for the iOS Simulator succeeded. No simulator or device run.
- Live, Claude: a 2.1.287 turn started with `effort: "low"` and `ultracode: true` recorded `effort: "low"` and entered Ultracode. `/usage`, `/context`, `/recap`, `/rename`, `/autocompact`, `/mcp` and `/doctor` were each run headless. The AGENTS.md rule was confirmed with `/context` in projects with no CLAUDE.md, a root CLAUDE.md, and a `.claude/CLAUDE.md`.
- Live, Codex: MCP server elicitations were exercised against the real 0.159.3 app-server with a throwaway MCP server and no model turn: form accept with content, decline, cancel, link accept, and `serverRequest/resolved` after each. MCP tool-call approvals and terminal-input approvals need a model turn to trigger and are covered by unit tests only.
- Browser QA on a standalone build (port 19385, temporary data directory): a `/usage` session shows its output, Ultracode stays on while the effort slider moves, and the new commands appear in slash suggestions. Screenshots are in `artifacts/cli-catchup/` (`2026-10-01-*.png`, not tracked).
- Not exercised: the Electron app, remote devices, and an end-to-end Codex conversation in the UI.
