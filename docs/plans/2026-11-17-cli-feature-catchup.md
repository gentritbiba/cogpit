# CLI compatibility audit — 2026-11-17

Cogpit now targets Claude Code 2.1.326 through Agent SDK 0.3.326 and supports the applicable additions in Codex CLI 0.167.2.

## Comparison baseline and sources

The previous audit was [October 22, through Claude Code 2.1.306 and Codex 0.163.0](2026-10-22-cli-feature-catchup.md). This one covers Claude Code 2.1.307–2.1.326 and Codex stable releases 0.164.0–0.167.2. Codex 0.168.0 and 0.169.0 (2026-11-13) are not covered; 0.167.2 was installed.

Primary sources:

- [Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md), entries 2.1.307–2.1.326.
- Agent SDK 0.3.326 TypeScript declarations (`sdk.d.ts`, `sdk-tools.d.ts`), diffed against 0.3.306.
- Codex release notes 0.164.0–0.167.2 and the app-server JSON schemas generated by 0.163.0 and 0.167.2, diffed.
- Live probes: headless SDK sessions on 2.1.306 and 2.1.326 (`supportedCommands()`, MCP set changes, mode switches, AskUserQuestion annotations, a broken global config, a Code Mode resume), and Codex app-servers 0.145.0–0.167.2 given an unknown model.
- Transcripts on this machine: record types, keys and weights written by Claude Code 2.1.307+ and Codex 0.164+, compared with the parsers and stores.

## Implemented

### Claude Code

| Change | Cogpit behavior |
| --- | --- |
| Claude SDK update | 0.3.306 → 0.3.326. |
| Asks in bypass mode (2.1.323, 2.1.326) | The CLI now asks a person for some calls even in bypass mode, including the MCP sign-in confirmation. Cogpit used to approve every ask in bypass mode; every ask the CLI raises now reaches the approval bar. Switching a live session to bypass or acceptEdits approves pending asks only after the CLI confirms the switch, and never asks marked `defaultToNo` or `suppressAlwaysAllowRule`. |
| "Always allow" | Only the CLI's suggested rules go back as `updatedPermissions`; asks without suggestions offer allow and deny. The whole-tool `sessionAllowedTools` list, which let one "always" approve every later call of a tool and survived resume, is removed. |
| Bypass at launch | Every Claude session starts with `allowDangerouslySkipPermissions`, so it can be switched to bypass later; a session with no requested mode starts in bypass. As root outside a sandbox (`IS_SANDBOX` unset) the CLI refuses that flag, so neither applies there. The mode a session starts in is stored and shown; clients seed an empty session config with `PUT /api/session-config/:key?fill` so they never overwrite it. |
| Permission mode read-back | `permissionMode` on `system/init` and `system/status`, compared with the stored config, becomes the session's mode (auto falls back to Manual where unavailable, plan approval moves a session on). The server stores it and sends `session-config`; a refused switch keeps the real mode and shows the CLI's reason. |
| MCP set changes | Servers passed at launch stayed connected after `setMcpServers` removed them (live on 2.1.306 and 2.1.326). The launch set is handed to `setMcpServers` at the first MCP change; doing it at start restarts those servers mid first turn. |
| `mcpServersDelivery` | `initialize` when the resolved CLI is at least 2.1.326, otherwise `argv`; keeps MCP credentials out of process listings on shared hosts. |
| Skipping questions | AskUserQuestion answers may carry `annotations.unanswered` (`ask_user_question_unanswered_v1`). The question card and Mission Control have Skip; a composer message while a question waits answers it as `replied_in_chat`; `cogpit-session answer ID --skip`. Older CLIs get the plain answer. Transcripts show Skipped / Replied in chat / Dismissed. Gated by the descriptor capability `skipQuestions`. |
| CLI notices | `system/informational` records (notice, suggestion, warning levels) render as quiet lines in their turn and in `session-context` / `cogpit-memory context`. `info` level is skipped, as in the CLI. |
| Fork subagents | Fork transcripts start with `fork-context-ref` and the parent's own Agent call. The sub-agent view starts at the fork's directive; the inherited call and fork boilerplate are hidden. |
| `config_file_invalid` | Classified as `config_invalid` with `File:` / `Backup:` lines; the error banner offers Restore from backup. `POST /api/agent-check/restore-config` restores only a file/backup pair a failed start reported, only the global `.claude.json` from its own `backups/`, and only from valid JSON. |
| Session archive (SDK 0.3.326) | Archiving or restoring a Claude session in Cogpit also calls the SDK's `archiveSession` / `unarchiveSession` (explicit user actions only, best effort). The session catalog reads the CLI's `archived.json` marker with an mtime-keyed cache, so sessions archived elsewhere show as archived; the newest of Cogpit's archive, Cogpit's restore and the CLI marker wins (archive file version 3 records restore times). |
| Errors after a failed turn | A crash in a later turn is reported as itself, not as the earlier turn's error result. |
| Code Mode sessions | Resuming one from the SDK fails; the banner says it continues only in a terminal and offers the resume command to copy. Cogpit never runs a command taken from an error message. |
| `session_writes_lost` | Shown in the turn-error banner (disk full or quota). The CLI sends it only when it exits by itself. |
| `credential_expires_at` | A dismissible notice above the composer within 7 days of the sign-in ending, with the existing sign-in action. |

### Codex

| Change | Cogpit behavior |
| --- | --- |
| Unknown models | No Codex version from 0.145 to 0.167.2 rejects an unknown model on `thread/start`, `turn/start` or `thread/resume`; the turn fails about 3 s later (`codexErrorInfo: "modelNotFound"` on 0.165+, raw `model_not_found` JSON before). The mid-turn model fallback reacted only to a thrown request and never fired. A refused model is now the failure reason `model_unavailable` ("Codex can't use that model. Pick another model."); a turn that ran on a model picked mid-turn is followed by an empty-input turn on the thread's last model, which answers the already recorded message. A later send naming no model goes back to the last model a turn ran on cleanly. Verified live on 0.167.2: an empty-input `turn/start` after the refusal answers the recorded message without adding a new one. |
| Models | The fallback catalog has gpt-6.2-sol (the new default), gpt-6.2-astra and gpt-6.1-terra in `model/list` order. |
| Protocol | Pinned to 0.167.2. `thread/section/changed` and `feedback/save` need nothing. |
| Plans | New plan ids (`sci`, `sci_plus`, business/enterprise variants) are named as Codex's `/status` names them; the workspace name shows next to the plan. |
| Duplicate `item_completed` events | 24–57% of recent rollout bytes. A prefix check drops them, except `SubAgentActivity`, from pages, `/api/watch` and status scans. First tail pages carry the same turns in 10–45% fewer bytes. |

## Changes handled by existing integration

Claude: `supportedCommands()` names are identical on 2.1.306 and 2.1.326. Fable 5.2 and other models come from the live catalog. No new transcript record type is heavy in the tail window; new metadata records and keys are ignored safely. The no-fallback refusal is followed by an API-error reply Cogpit already shows. Opus 4.8 fast mode (ending 2026-11-30) is offered only when the live catalog says so.

Codex: `ServerRequest.json` methods are unchanged. Idle threads unload after a minute, and Cogpit resumes before every turn. Resume keeps a thread's saved model and effort; Cogpit sends neither for Default. The new rollout records (`additional_tools`, `configuration_update`) are ignored; first lines stay under the 32 KB the listing reads. `humanCommand` approvals go only to experimental clients.

## Explicit boundaries

- A pending ask the CLI would also raise in bypass mode but marks with neither `defaultToNo` nor `suppressAlwaysAllowRule` is still approved when the user switches to bypass while it waits; nothing distinguishes it.
- Session-scoped "always allow" rules now live only in the CLI process and end with it, as in the terminal.
- `session_writes_lost` may never arrive when Cogpit itself stops the CLI.
- Restore from backup is offered only for the default account; account instances fail inside their own worker. The restore writes a temp file and renames it.
- Mode changes the CLI makes in an account-instance worker (after the start) are written to the worker's config store and do not reach the UI.
- CLI-driven mode changes are not in the team edition's `session.config` audit log; that needs an edition hook (`onAgentConfigChange`) since the change has no request actor.
- Cogpit unarchives a CLI-archived session on any transcript write more than 2 minutes after the mark (its own rule); the CLI unarchives on a newer human prompt.
- The text-based Codex model retry stays for the legacy `codex exec` path; the thrown app-server rejection path (`MODEL_REJECTED`) is removed because no Codex from 0.145 to 0.167.2 throws it.
- gpt-6.2-sol and gpt-6.2-astra are unpriced until LiteLLM lists them.

Four tests timed out under load and passed when rerun alone. cogpit-memory: every test file passed, run one at a time. The suite without the team edition was run separately.
